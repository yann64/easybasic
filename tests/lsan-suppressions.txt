# LeakSanitizer suppressions for known, intentional third-party "leaks" -
# not bugs in pbcxx or its runtime. Referenced by CMakePresets.json's
# linux-clang-sanitize test preset and ci.yml's sanitizers job via
# LSAN_OPTIONS=suppressions=<this file>.
#
# fontconfig/pango-ft2 keep a process-lifetime font-config cache alive
# deliberately (first touched by gtk_init, via guilib.hpp - M7b) - this is
# a well-known false positive for GTK/Pango-linked programs under ASan's
# leak detector, not a real leak: the allocation is reachable for the
# program's entire lifetime and freed by the OS at process exit.
leak:libfontconfig.so
leak:libpangoft2

# at-spi2/ATK's own accessibility-bridge adaptor does similar process-
# lifetime, one-time setup allocations on gtk_init - also a false positive,
# confirmed on GitHub Actions' ubuntu-latest runners specifically (not
# reproduced on this project's own dev machine, which installs a leaner
# GTK3 dependency set without the AT-SPI D-Bus bridge pulled in).
leak:atk_bridge_adaptor_init

# GtkFileChooserDialog (OpenFileRequester/SaveFileRequester/
# PathRequester - M7b's Requester slice) kicks off its own asynchronous
# default-folder enumeration via GIO on construction; cancelling quickly
# (as this project's own unit tests do, via a 50ms g_timeout_add) destroys
# the dialog while that operation is still in flight, abandoning its own
# internal GTask/GLocalFile/GError/canonicalized-path objects - confirmed
# entirely inside libgtk-3.so/glib/gio's own internals
# (g_local_file_get_parent for Open/Save, g_cancellable_set_error_if_cancelled
# for the folder-only chooser PathRequester uses), not caused by anything
# pbOpenFileRequester/pbSaveFileRequester/pbPathRequester do themselves; a
# real, interactive accept/cancel (not a 50ms-later synthetic one) gives
# the async operation time to finish and clean up normally.
leak:g_local_file_get_parent
leak:g_cancellable_set_error_if_cancelled
# The two function-name suppressions above only match on a machine with
# GLib/GIO's own debuginfo installed (this project's own dev machine) -
# confirmed to still leak straight through on GitHub Actions'
# ubuntu-latest runner, where those internal (non-exported) GIO symbols
# come back unresolved ("libgio-2.0.so.0+0x1351b0", not a name LSan's
# pattern matching can compare against), unlike `gtk_dialog_run` itself
# a few frames up (a public, always-exported GTK symbol, resolved fine
# either way). A library-level suppression - the same granularity
# fontconfig/pango-ft2's own already use above, for the same underlying
# reason - is the only form robust to that, so both are kept: the
# function-level ones as the more precise, documented mechanism, and this
# one so the gate actually passes in CI too.
leak:libgio-2.0.so
